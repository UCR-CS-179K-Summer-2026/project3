Query Features

The JSON Query Engine supports three primary commands: FIND, DISPLAY, and FILTER. Together, these commands allow users to verify JSON paths, retrieve values, access nested arrays and objects, and filter records using supported conditions.

Learn the Query Syntax Getting Started

Supported Commands

All three commands use the same nested query structure, but each command performs a different operation on the loaded JSON document.

FIND

Checks whether a requested key, array position, or nested JSON path exists.

Returns: true or false

DISPLAY

Traverses the JSON document and returns one or more requested values.

Returns: JSON value(s)

FILTER

Searches records inside a JSON array and returns objects whose selected field matches a supported filter condition.

Returns: matching JSON object(s)
The examples below show only the portions of the JSON document relevant to each query. Full datasets are available in the project repository.

Understanding Query Structure

Queries use nested braces to describe movement through the JSON document. Each nested group represents another level of navigation.

Nested Groups Mean Descend

DISPLAY {"users" {1 {"profile" {"location" {"city"}}}}}

This query is interpreted as:

  1. Locate the top-level users key.
  2. Enter the users array.
  3. Select array element 1.
  4. Enter that user's profile object.
  5. Enter the location object.
  6. Locate the city field.

Multiple Keys at the Same Level

DISPLAY {"users" {1 {"name" "email" "score" "active"}}}

The four keys inside the innermost group are sibling values. The engine retrieves each value from the same user object.

Nested braces indicate deeper JSON traversal. Multiple values written side-by-side inside the same group represent multiple targets at the same JSON level.

FIND

FIND checks whether all requested components can be located in the JSON document.

Unlike DISPLAY, FIND does not return the stored JSON value. It returns a Boolean result indicating whether the requested structure exists.

Example: Find a Deeply Nested Field

Relevant JSON Excerpt

{
  "users": [
    {
      "name": "Laura Chen"
    },
    {
      "name": "Marco Ruiz",
      "profile": {
        "location": {
          "city": "Austin",
          "state": "TX",
          "zip": "78701"
        }
      }
    }
  ]
}

Query

FIND {"users" {1 {"profile" {"location" {"city"}}}}}

Result

true

The query first selects user 1, then traverses through profile and location. The query returns true because the city field exists.

FIND is useful when a user wants to verify the existence of a JSON path before requesting its value.

DISPLAY

DISPLAY navigates through the JSON document and returns the value or values found at the requested location.

Example 1: Retrieve a Single Value

Relevant JSON Excerpt

{
  "users": [
    {
      "name": "Laura Chen"
    },
    {
      "name": "Marco Ruiz"
    }
  ]
}

Query

DISPLAY {"users" {1 {"name"}}}

Result

"Marco Ruiz"

The engine selects array element 1 from users and returns its name value.

Example 2: Retrieve Multiple Fields

Relevant JSON Excerpt

{
  "name": "Marco Ruiz",
  "email": "marco@example.com",
  "score": 78.25,
  "active": true
}

Query

DISPLAY {"users" {1 {"name" "email" "score" "active"}}}

Result

["Marco Ruiz", "marco@example.com", 78.25, true]

Multiple requested fields are collected in the same order they appear in the query.

Example 3: Retrieve Nested Location Data

Relevant JSON Excerpt

{
  "profile": {
    "location": {
      "city": "Austin",
      "state": "TX",
      "zip": "78701"
    }
  }
}

Query

DISPLAY {"users" {1 {"profile" {"location" {"city" "state" "zip"}}}}}

Result

["Austin", "TX", "78701"]

This example combines deep traversal with multiple values at the final level of the query.

Example 4: Retrieve Nested Preferences

Relevant JSON Excerpt

{
  "profile": {
    "preferences": {
      "theme": "light",
      "density": "comfortable"
    }
  }
}

Query

DISPLAY {"users" {1 {"profile" {"preferences" {"theme" "density"}}}}}

Result

["light", "comfortable"]

Example 5: Retrieve Deep Notification Settings

Relevant JSON Excerpt

{
  "notifications": {
    "email": false,
    "push": true,
    "digest": "daily"
  }
}

Query

DISPLAY {"users" {1 {"profile" {"preferences" {"notifications" {"email" "push" "digest"}}}}}}

Result

[false, true, "daily"]

DISPLAY can return JSON values of different types in the same result, including booleans and strings.

Example 6: Access an Array Element

Relevant JSON Excerpt

{
  "roles": [
    "contributor"
  ]
}

Query

DISPLAY {"users" {1 {"roles" {0}}}}

Result

"contributor"

Numeric components can be used to select an element from a JSON array.

Example 7: Query an Object Inside an Array

Relevant JSON Excerpt

{
  "history": [
    {
      "event": "login",
      "ip": "10.0.0.9"
    },
    {
      "event": "comment",
      "target": "pr/318"
    }
  ]
}

Query

DISPLAY {"users" {1 {"history" {1 {"event" "target"}}}}}

Result

["comment", "pr/318"]

This query enters the user's history array, selects history element 1, and retrieves two fields from that object.

DISPLAY supports both single-value and multi-value results. It can navigate through nested objects, arrays, and arrays containing objects.

FILTER

FILTER searches objects within a selected JSON array. The engine examines a requested field and returns the complete object when the value satisfies the filter.

Numeric Range Filtering

A numeric FILTER uses two numbers after the query path: a lower bound and an upper bound. 

FILTER {"users" {"score"}} 70 80

Conceptually, a numeric value matches when: 

lower bound ≤ value ≤ upper bound

Relevant JSON Excerpt

{
  "users": [
    {
      "name": "Laura Chen",
      "score": 91.5
    },
    {
      "name": "Marco Ruiz",
      "score": 78.25
    },
    {
      "name": "Priya Nair",
      "score": 64.0
    }
  ]
}

Query

FILTER {"users" {"score"}} 70 80

Result

{
  "id": 1002,
  "name": "Marco Ruiz",
  "email": "marco@example.com",
  "active": true,
  "score": 78.25,
  "roles": [
    "contributor"
  ],
  "profile": {
    ...
  },
  "history": [
    ...
  ]
}

Marco Ruiz is returned because the score 78.25 falls between 70 and 80.

FILTER returns the complete matching JSON object, not only the field that was evaluated.

Regular Expression Filtering

FILTER also supports regular-expression matching on string fields. The regular expression is written after the query path.

Relevant JSON Excerpt

{
  "users": [
    {
      "name": "Laura Chen"
    },
    {
      "name": "Marco Ruiz"
    },
    {
      "name": "Priya Nair"
    }
  ]
}

Query

FILTER {"users" {"name"}} "^M"

Result

{
  "id": 1002,
  "name": "Marco Ruiz",
  "email": "marco@example.com",
  "active": true,
  "score": 78.25,
  "roles": [
    "contributor"
  ],
  "profile": {
    ...
  },
  "history": [
    ...
  ]
}

The pattern ^M matches strings that begin with the letter M. Because Marco Ruiz matches that pattern, the complete user object is returned.

Regex FILTER returns the full matching JSON object rather than only the field used for comparison.

Query Formatting Rules

The following rules help explain how the current query syntax should be written.

  • Commands are written before the query group: FIND, DISPLAY, or FILTER.
  • Object keys are generally written inside double quotes.
  • Nested braces indicate movement deeper into a JSON value.
  • Array positions may be represented by numeric query components such as 0 or 1.
  • Multiple values at the same level can be written side-by-side inside the same query group.
  • String FILTER arguments are written after the query group and enclosed in quotation marks.
  • Numeric FILTER bounds are written after the query group without quotation marks.

Supported JSON Structures

The query engine is designed to work with a variety of JSON structures and value types.

Objects

Query object keys and descend through deeply nested object structures.

Arrays

Select specific array elements and continue querying values inside those elements.

Arrays of Objects

Navigate into array elements that contain additional nested JSON objects.

Multiple Values

DISPLAY can return several sibling fields in a single query.

Mixed JSON Types

Results can include strings, numbers, booleans, arrays, objects, and other JSON values.

Deep Nesting

Recursive query groups support traversal through multiple nested levels.

Command Comparison

Command Purpose Example Result Type
FIND Verify that a requested JSON structure exists. FIND {"users" {1 {"profile"}}} true or false
DISPLAY Retrieve one or more values from a JSON path. DISPLAY {"users" {1 {"name"}}} JSON value or value list
FILTER Return objects whose selected field satisfies a supported condition. FILTER {"users" {"score"}} 70 80 Matching JSON object(s)

Current Feature Scope

The current user-facing query language focuses on FIND, DISPLAY, and FILTER.

Working Features

  • Nested FIND queries
  • Single-value DISPLAY
  • Multi-value DISPLAY
  • Nested object traversal
  • Array index traversal
  • Arrays containing objects
  • Boolean, numeric, and string results
  • Numeric range FILTER
  • Regular-expression FILTER

Behavior Being Improved

  • Clearer invalid-query diagnostics
  • Clearer invalid-path diagnostics
  • Additional end-to-end command testing
