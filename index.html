JSON Query Engine — Architecture, Design, and Algorithms

The JSON Query Engine is a C++20 project for querying structured JSON data. The system separates query processing from JSON processing: one subsystem parses and interprets user queries, while the other traverses JSON objects and arrays to retrieve the requested value.

The current repository includes a recursive query parser, a query reader that builds QueryConstruct objects, a pointer-oriented JSON traversal engine, a command-line interface, automated GoogleTest suites, JSON edge-case fixtures, and performance benchmarks. The remaining integration work is the execution layer that connects a complete QueryConstruct to JSON traversal.

System Architecture

At a high level, the system is designed as a pipeline. JSON data and a user query enter through separate paths, then meet at the execution layer. The query side determines what operation should happen; the JSON side provides the data that operation acts on.

Query parsing, query interpretation, and JSON traversal are implemented, but applyquery() is still the missing bridge between the interpreted query and the JSON engine. The current main.cpp therefore sends a whitespace-split path directly to parsejson() as a temporary interface.

System Design

The design separates responsibilities so that query syntax, query meaning, JSON traversal, and user interaction can evolve independently. This also makes individual components easier to unit test.

Internal System Design

Main Program

main.cpp is the command-line controller. It asks for a JSON filename, verifies that the file opens, loads the JSON text, accepts repeated user input, calls the JSON parser, and prints the returned value.

Its current query input logic is intentionally temporary: it splits a line on whitespace into a std::vector<std::string> and passes that path directly to json_parser::parsejson(). Once the execution layer is complete, this path will be replaced by the full parser → reader → executor pipeline.

Query Parser

The query parser is implemented in include/queryparser.h and src/queryparser.cpp. It converts raw query text into a recursive structure made from JSONType values. 

struct JSONType {
    std::variant<
        std::string,
        std::vector<JSONType>
    > structure;
};

This recursive representation is necessary because a query element may be either a normal string token or another nested group. For example: 

FIND {a b {c d {e f}}}

can be represented conceptually as:

[
    "FIND",
    [
        "a",
        "b",
        ["c", "d", ["e", "f"]]
    ]
]

Query Reader

The query reader is implemented in include/queryreader.h and src/queryreader.cpp. Its responsibility is different from parsing: the parser determines the syntax structure, while the reader determines the meaning of that structure. 

enum class Query {
    FIND,
    FILTER,
    DISPLAY,
    ALLOF
};

readquery() reads the first parsed token as the command, treats the next recursive element as the key/path structure, collects any remaining values as parameters, and returns a QueryConstruct. 

struct QueryConstruct {
    Query query;
    std::vector<JSONType> keys;
    std::string param;
    std::vector<JSONType> params;

    bool isregexquery = false;
    bool isparamsquery = true;
};

When a query contains one string parameter, the current reader also attempts to compile that string as a regular expression. A valid expression is marked as a regex query; otherwise it is kept as a normal string parameter.

Query Execution Layer

The execution layer is represented by queryreader::applyquery(). Its intended role is to take a fully interpreted QueryConstruct and execute the corresponding operation against the JSON data.

Current status: applyquery() is declared and present in the source, but its body is still marked // To be implemented. This is the main integration point still under development.

JSON Parser

The JSON parser is implemented in include/jsonparser.h and src/jsonparser.cpp. It receives JSON text and a path of object keys and array indices, then follows that path to return the raw JSON value at the selected location. 

std::vector<std::string> path = {
    "employees",
    "0",
    "name"
};

The path above means:

  1. Find the object key employees.
  2. Enter array index 0.
  3. Find the object key name.
  4. Return the raw JSON value at that position.

Core Data Structures

JSONType

Represents recursive query syntax. A value can hold either a string token or another vector of JSONType values.

Why it matters: nested braces can be preserved instead of flattened.

QueryConstruct

Represents an interpreted query after parsing. It stores the operation, keys, optional string parameter, optional parameter list, and flags used to distinguish regex-style and parameter-style queries.

Why it matters: execution code does not need to reinterpret raw text.

Module Interfaces

File Validation

int json_parser::isFileOpen(std::ifstream& json);

Checks whether the input stream is open. The parser tests also exercise the older json_parser::test() helper for open/missing-file behavior.

Convert a JSON File to a String

std::string json_parser::jsonToString(std::ifstream& json);

Reads the complete contents of a JSON file into an owning std::string so the parser can scan it in memory.

Traverse JSON Data

std::string json_parser::parsejson(
    std::string_view json,
    const std::vector<std::string>& query
);

Traverses the JSON according to the requested path and returns the matching raw JSON text. If the path cannot be resolved, the result is empty.

Parse a Query

void queryparser::parsequery(const std::string& query);

Parses raw query text and stores the resulting recursive query representation.

Retrieve the Parsed Query

const std::vector<JSONType>&
queryparser::getparsedquery();

Interpret a Parsed Query

const QueryConstruct queryreader::readquery(
    const std::vector<JSONType>& parsedquery
);

Converts the parser output into a command-oriented QueryConstruct that can later be executed against the JSON data.

Algorithms

1. Query Parsing Algorithm

The query parser scans the input one character at a time and builds recursive groups when it encounters braces.

  1. Collect normal characters into the current token.
  2. Use whitespace to separate tokens.
  3. When an opening brace is found, begin a nested group.
  4. Parse the contents of the group recursively.
  5. When the matching closing brace is found, return to the previous level.
  6. Store the final structure as std::vector<JSONType>.

2. Query Interpretation Algorithm

  1. Read the first parsed token and map it to the Query enum.
  2. Read the second parsed element as the key/path structure.
  3. Collect all remaining elements as optional parameters.
  4. If one string parameter exists, test whether it is a valid regular expression.
  5. Return the appropriate QueryConstruct.

3. JSON Traversal Algorithm

JSON Traversal Flowchart

The traversal processes one path component at a time. At each step, the parser determines whether the current JSON value is an object or array and uses the component accordingly.

Object Lookup

  1. Scan each quoted key.
  2. Compare it with the current path component.
  3. Skip the value of nonmatching keys.
  4. Continue from the matching key's value.

Array Lookup

  1. Convert the path component to an index.
  2. Walk through array elements.
  3. Skip elements before the requested index.
  4. Continue from the selected element.

4. Value Skipping

A major helper operation is skipping values that are not part of the requested path. The parser can move past strings, numbers, booleans, null, objects, and arrays without fully materializing them as C++ objects. Nested objects and arrays are skipped by tracking structural depth until the complete value has been passed.

Design Decisions & Optimizations

Direct JSON Scanning

The parser scans the original JSON text instead of building a complete in-memory JSON object tree. This reduces object allocation and allows the engine to ignore data that is unrelated to the requested path.

Skip Irrelevant Values

During object and array traversal, unmatched values are skipped rather than fully parsed. The search can also stop once the requested value has been located.

std::string_view During Scanning

The parser accepts the JSON input as std::string_view, which allows it to inspect the existing string buffer without first duplicating the entire document.

Recursive Query Representation

JSONType preserves nested query groups directly. This keeps syntactic structure available to later stages instead of flattening the query and then attempting to reconstruct it.

Unicode and Escape Handling

The JSON parser includes handling for escaped strings, Unicode escape sequences, UTF-8 keys, and surrogate-pair cases. These behaviors are important because object-key comparison must work even when the JSON encodes text differently from the user-facing key.

Testing Strategy

The project uses GoogleTest for correctness testing and a separate benchmark executable for timing experiments. Parameterized tests are used when several inputs should satisfy the same behavior, which keeps the assertions consistent while still giving each case a descriptive name.

Area What is verified Why it matters
File handling Basic fixtures open, missing/empty filenames fail, repeated open checks remain valid, and files convert to strings. Confirms the parser starts from a reliable input source.
Basic JSON traversal Object keys, array indices, nested objects, nested arrays, strings, integers, decimals, and missing keys. Exercises the main lookup algorithm on representative paths.
Escapes & Unicode Escaped quotes, unusual keys, raw UTF-8, Unicode escapes, and surrogate-related cases. Checks that key comparison works across JSON string encodings.
Literal & edge values null, booleans, negative numbers, exponent notation, escaped null sequences, embedded raw null bytes, empty arrays, and empty objects. Protects against parser failures outside simple textbook JSON.
Query parsing Simple and multi-field queries, array-index tokens, nested/deep groups, repeated whitespace, quoted tokens, empty input, malformed braces, and replacement of prior parser state. Verifies recursive syntax construction and parser state management.

Representative Test Pattern

Many traversal checks use one parameterized test with different fixture/path/expected-value cases. This makes it easy to add coverage without duplicating the same setup and assertion logic. 

TEST_P(JsonBasicParseTest, ReturnsExpectedValue) {
    const auto& test = GetParam();
    std::ifstream file(test.filename);
    ASSERT_TRUE(file.is_open());

    const std::string jsonText = json_parser::jsonToString(file);
    const std::string result = json_parser::parsejson(jsonText, test.path);

    EXPECT_EQ(result, test.expected);
}

Performance Benchmarks

benchmark.cpp is separate from the correctness suite. It can compare lookup timing on approximately 1 KB and 1 MB booking datasets, and it also measures a spread of paths through big.json, including early/late object keys, missing keys, Unicode/escaped keys, deep paths, array indexing, long escaped values, and a value near the end of the document.

Testing gap to address next: the repository currently has strong parser and JSON-traversal tests, but the query-reader/execution pipeline should gain dedicated tests as applyquery() is implemented. The most important additions will be command interpretation tests for FIND/FILTER/DISPLAY/ALLOF and end-to-end tests from raw query text to returned JSON result.

Sample and Stress-Test Data

The repository includes several groups of JSON fixtures:

  • jsonFiles/basic/ — employee, product, and university examples
  • jsonFiles/edgecases/ — embedded nulls, literal types, and empty structures
  • jsonFiles/unicode/ — escaped quotes, unusual keys, and Unicode cases
  • Bookings_1-level_1-KB_formatted.json and Bookings_1-level_1-MB_formatted.json — benchmark inputs
  • big.json — broader traversal and performance stress cases

Together, these files exercise shallow and deeply nested structures, objects, arrays, strings, numeric literals, booleans, null, Unicode text, escaped content, missing values, and larger documents.
